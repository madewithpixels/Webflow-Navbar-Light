## Published checks

Method: Chrome on the published `webflow.io` pages. The automation tab reported `visibilityState: hidden` with no animation frames, so transitions could not advance and window resizing had no effect. Breakpoints were therefore tested in same-origin iframes of the published page at exact widths. End-state geometry was measured with a test-only `transition: none` style inside the iframe. Reduced motion was simulated by injecting the delivered stylesheet's own `@media (prefers-reduced-motion: reduce)` rules unconditionally inside the iframe. The JavaScript `matchMedia` reduced-motion branch is covered by the automated suite, not this browser run.

## Visible-window keyboard and motion checks (SB Test Five, published)

Run later the same day in a foreground Chrome window at 600px, using real key events and the real macOS Reduce motion setting.

- Tab order to the menu: Brand → Menu trigger, with `:focus-visible` on the summary.
- Reduce motion **on** (`matchMedia` true): Enter opened the menu. `mwp-nav:open` → `opened` took 1ms (the JavaScript reduced-motion path); panel ran at `0.01ms, 0.01ms, 0s` and items at `0.01ms`. The X was fully formed within 120ms with all bar centres at (12, 8), and the backdrop showed. Space also opened the menu.
- Nested submenu: Enter on "More" opened it, Tab reached its first link, and the chevron rotated (`0.01ms`). The first Escape closed only the submenu and focused "More"; the second closed the menu, restored `inert` and `aria-hidden`, cleared the backdrop and returned focus to the trigger with `:focus-visible`. Events fired open → opened → close → closed.
- Icon thickness matrix (test-only page override of bar height and gap, both icon modes): 1px/4px, 2px/5px, 3px/6px, 3px/7px and 4px/4px all measured auto-shift = height + gap, and every visible bar centre converged.
- Full-width backdrop (test-only layout switch): backdrop opacity 1, panel 0–600px, no overflow, page scroll not locked.
- Reduce motion **off**: real Enter opened in 281ms (configured 280ms) and Escape closed in 222ms (configured 220ms). Panel and item opacity followed the eased curve (open ≈ 0.53 at 48ms, 0.93 at 129ms; close ≈ 0.37 at 49ms, 0.03 at 129ms), and the middle burger bar crossed over in step.

### Finding: panel focus order does not match visual order (WCAG 2.4.3)

In the collapsed panel, keyboard and accessibility-tree order runs through all nine Secondary links (Facebook … Email) before Home, CDN build, Self-hosted, Style guide, More and View release. The runtime CSS shows Primary first (`order: 0`) and Secondary second (`order: 1`), while the native component keeps `Secondary navigation` first in the DOM. In the expanded layout, the native `mwp-css-nav_panel` flex row has no `order`, so Secondary currently renders to the left of Primary. Fixing this needs a deliberate structural decision; it is tracked in `todo.md`.
