# SmashBurger Designer Extension capability prototype

This is a **private, disposable API test**, not a SmashBurger installer. It has these actions:

- **Inspect selection** reads the site breakpoints, selected component origin, variants, property groups and instance overrides, root marker, recognizable runtime hooks in WHTML, and whether WHTML export is available.
- **Create native proof** inserts a small editable header on a selected page container, gives it reusable `sb-proof-*` classes with styles at every configured breakpoint, converts it to a project component, creates the five planned collapse variant names, adds grouped properties, and attempts to bind those properties to native `aria-label` attributes.
- **Create draft lab and proof** finds or creates the unpublished `smashburger-app-api-lab` page on the Smashburger test site and runs the native proof on its Body. It refuses a duplicate proof component and checks the saved variants, properties and bindings.
- **Verify existing proof** reads the saved component, its variants, authored properties and two `aria-label` bindings without changing the site. Webflow also creates its own `Variant` property; the verifier allows for that generated property.
- **Check styles + Embed API** reads the proof class properties at all seven breakpoints. On the draft lab page only, it inserts or reuses one marked Code Embed and checks whether the Designer API exposes a code setting that can save a harmless HTML comment. It does not add production CSS or JavaScript.
- **Create native core trial** uses the working direct-append API to build a small functional header from native Webflow elements on the draft page: a details/summary trigger, shared links, breakpoint styles, runtime hooks and a pinned `v0.2.3` loader Embed inside a compact, Canvas-visible infrastructure Details. It registers a separate project component and refuses a duplicate. This is a trial of the installer route, not the full 57-property SmashBurger component.
- **Configure native core trial** adds twelve grouped native Webflow properties to the draft component and binds them to layout, motion, behavior and accessibility attributes. It also reuses or creates the compact runtime Details, verifies its saved structure and bindings, and can be rerun without creating duplicate properties.
- **Configure native content trial** checks whether this Designer session can bind each native link's text and destination, then preserves the current values as eight grouped component properties. It verifies the saved bindings and can be rerun without adding duplicate properties.
- **Build native primary navigation** moves the three existing links into a marked primary wrapper, adds a native editable CTA, and binds four boolean visibility properties for the menu label, backdrop, primary navigation and CTA. It checks the saved structure and bindings and can be rerun without duplicating them.
- **Build native submenu** adds a draft-only `details`/`summary` submenu with two editable native links, Designer classes for expanded and Tablet layouts, and scoped open-state rules in the pinned runtime Embed. It refuses unexpected primary children and checks the saved submenu structure before reporting success. Live Designer and independent Data API readback passed; Michael confirmed Desktop and Tablet Preview layout and behavior.
- **Bind native submenu properties** adds eight draft-only controls for arrow visibility, icon motion, and the two submenu links' text and destinations. It checks the native targets before adding properties and reads every saved binding back. Live Designer and independent Data API readback passed.
- **Bind native motion controls** adds seven draft-only properties for panel travel, easing, opening and closing duration, item stagger, burger icon duration, and two or three icon lines. It binds each to a root attribute already read by the pinned runtime. Live Designer and independent Data API readback passed.
- **Check install target (read only)** reports whether the current page is draft and editable, whether SmashBurger components or a marked navbar already exist, whether the three responsive breakpoints and asset permissions are available, and how many bundled icons this app can see. It makes no site changes. This is an installer preflight, not an installer.
- **Install complete alpha on clean draft** reruns preflight and runs the proven core, content, icon and variant phases in order, reporting progress. It stops on the first failed phase and leaves the partial draft inspectable for recovery through the individual phase actions. The one-click run succeeded on the blank draft `sb-test` page of `another disposable site`; it is still an alpha installer, not the production release.
- **Install native alpha on draft page** reruns that preflight, then creates one project-native core header and pinned runtime Embed on a clean draft page. It marks the root immediately so a stopped run cannot silently duplicate it. This is an incomplete installation fixture with basic links, not a production navbar or full installer. A clean-site Designer run on the draft `sb-test` page succeeded.
- **Expand native alpha on draft page** reuses the trial's guarded, repeatable native actions to add primary navigation, text-only social/contact links, the submenu, and content, visibility and motion controls to that one alpha instance. A stopped run leaves inspectable draft content and may be retried after inspection. A clean-site Designer run saved 62 properties on `sb-test`.
- **Bind alpha CTA content** checks the one editable native alpha component and its marked CTA, preserves the current CTA text and destination, and binds them to two grouped component properties. It is included in new one-click installs and can be run separately on an existing draft alpha. The separate action passed Designer binding readback on `another disposable site`; instance override and Preview checks are still pending.
- **Install native alpha icons** adds a native Image to each of the nine secondary links, uploads or reuses the bundled SVG assets, and binds nine replaceable image properties. It refuses unexpected link structure, duplicate app-visible asset names or conflicting property defaults. The clean-site Designer run reported nine uploads and nine verified image bindings; read-only preflight found 9/9 assets. After a Designer refresh, custom-code Preview rendered the icons and panel at 2057px and 820px.
- **Repair alpha Tablet default** sets the unvarianted alpha's bound Collapse breakpoint property to `tablet` after validating its single instance and root marker. The clean-site Designer action passed readback, and Michael confirmed horizontal desktop links and a working 820px Menu trigger in Preview. New clean-site installs now start with that explicit default.
- **Configure native alpha variants** creates five collapse variants with Tablet as the base variant, bridges the selected variant to the runtime, and saves responsive Canvas styles. The clean-site action passed readback after correcting a `base` style-ID check; Michael confirmed all five collapse choices in Preview.
- **Probe proof variant attributes** temporarily writes a marker in the proof component's Always editing context, reads it from Base, removes it, and restores the selected variant. Open the proof with **Edit component** before running it.
- **Create core variant names** idempotently adds the five collapse choices to the draft native core.
- **Activate core variant bridge** makes a blank Collapse breakpoint property follow Webflow's generated variant marker and keeps a nonblank value as an explicit override. It updates only the known draft runtime Embed and reads its saved code back.
- **Style core variants** saves and reads back native Canvas styles at each variant's collapse threshold.

The proof deliberately has no SmashBurger runtime and its variant names do not yet alter collapse behavior. It must never be used as a production navigation menu. Run it only on a spare page or clone of the Smashburger site. It refuses a second run when the named component exists, and also checks for a partial native proof in the selected container. It reuses its styles if an earlier attempt stopped before component creation.

## Build and local run

```sh
npm ci
npx tsc --noEmit
npm run lint
npm run build
```

The bundle is `bundle.zip`. For live Designer testing, register a private Designer Extension app in the Webflow workspace, add its development URL or upload the bundle, and install it on the test site. The CLI scaffold alone does **not** install an app or prove the host API works. Use the Webflow CLI's current package `@webflow/webflow-cli`; the pinned version here is 2.9.0.

## Live acceptance to record

1. On the Smashburger test site, inspect a linked Library component and an unlinked native root. Confirm origin, marker, variants, props, and breakpoints.
2. On a spare page, create the proof and verify its Canvas structure, class styles at every site breakpoint, five variant names, grouped props, and both attribute bindings.
3. Close the Extension and verify the component and styles remain editable. Publish the spare page only if needed to inspect rendered output.
4. Reopen and run the action again. It must refuse duplicates. Test a partial failure separately on a clone.
5. Determine whether the API can insert and configure a Canvas-visible Embed, and whether WHTML import can safely preserve an adapted SmashBurger tree.

The production installer, Make local workflow, production Embed setup, rollback, and full functional/accessibility checks remain separate work.
